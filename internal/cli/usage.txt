--target is repeatable (default claude); pass it twice (--target claude --target
opencode) to install more than one layout in one run. The opencode target renders
skills into <target>/.opencode/skills and wires <target>/opencode.json (skills as
instructions + the gopls and dart MCP servers). Both opencode and the agents
target write <target>/AGENTS.md at the project root (carrying the routing
contract) from the same builder, so the file never diverges between them; agents
writes nothing else, for the AI coding agents (Codex, Gemini CLI, Zed, Amp,
JetBrains Junie, Jules, and others) that read a repo-root AGENTS.md and nothing
else. The cursor target renders skills into <target>/.cursor/rules as one .mdc
file per skill, each alwaysApply:false so Cursor pulls it in on demand by
matching its description, plus one small alwaysApply:true pointer rule carrying
the routing contract - Cursor injects every alwaysApply:true rule into every
request, so the full skill set (tens of KB) never goes on that path. The codex
target renders skills into <target>/.agents/skills (the root Codex reads), writes
<target>/AGENTS.md like the agents target, wires the skill-router hooks into
<target>/.codex/hooks.json (Codex dialect, found by a parent-walk from the working
directory, so no git is needed), and writes the gopls and dart MCP servers into
<target>/.codex/config.toml as one marked block that uninstall removes; a user's own
[mcp_servers.<name>] entry is never replaced. With --global, codex installs skills into
~/.agents/skills, and the hooks, AGENTS.md and config.toml under ~/.codex (or $CODEX_HOME
when set); a project install then takes over its own sessions. Codex asks you to trust the
project and approve the hooks once: run /hooks in Codex after install.

--layout applies a customization profile (e.g. monorepo | inner-modules) that
overrides which rules a skill composes; --interactive prompts for it when unset.

--preset selects an analyzer configuration preset for the governance subcommand
(recommended|strict|minimal). recommended keeps all analyzers with standard
thresholds; strict tightens the complexity analyzer (max_complexity 15 to 10,
max_func_lines 80 to 50, max_params 5 to 4) and states file-size's
max_lines=180, already its default; minimal disables the architecture and
golangci-lint analyzers, most AST checks, the style checks and
history-narration, keeping import-groups, naming, time-discipline,
pprof-labels and the other static checks, plus single-letter-name for
upper-case letters on functions, methods, types, constants, variables and
fields, locals included.

--scope limits the governance analysis to a subset of analyzers (full = all;
changed = static-gate (static, AST, commit) and architecture analyzers, skipping
the full-only analyzers (golangci-lint, branch-name, delegated commands);
commit = static-gate analyzers over files with a staged change; a partially
staged file is read from disk, unstaged hunks included). Use --scope commit in
pre-commit hooks for fast checks.

Flags must come before a positional argument: parsing stops at the first one, so
`pulsarules_cli list --root DIR rules` honors --root and `list rules --root DIR`
silently ignores it.

--config names the project config file that turns analyzers on or off, sets their
params and severity, scopes both to path globs and declares delegated commands.
Without it, the layers below are merged, each overriding the one before:
the user file <user-config-dir>/pulsarules/pulsarules.yaml (on Linux
$XDG_CONFIG_HOME or ~/.config), <project>/.pulsarules.yaml, then the private
<git-common-dir>/pulsarules.yaml. The preset comes from the highest layer that
names one. An unknown key or param is an error, and an invalid file fails
governance and the hooks. Precedence: built-ins, preset (--preset, else the
layers', else recommended), the layers, then the flags.

--golangci-config overrides the golangci-lint config discovery path. When unset,
the runner searches the project root, tools/, and build/ directories for
.golangci.yml, and on go.work repositories runs per-module.

install renders the selected skills into <target>/.claude/skills, installs the
skill-router reminder hook into <target>/.claude/hooks, and idempotently wires it
into the chosen settings file. --hooks-scope project (the default) wires into
<target>/.claude/settings.json; --hooks-scope local wires into
settings.local.json. The wired hook command locates the installed hook script
via $CLAUDE_PROJECT_DIR (a Claude Code variable, legitimately named there);
the script then exports PULSARULES_PROJECT_DIR and PULSARULES_SKILLS_DIR, the
only variables the binary itself reads, so generic Go stays host-neutral.
Unless --no-mcp is given and when gopls is on PATH, it also merges the gopls
server into <target>/.mcp.json and regenerates the gopls-navigation skill from
"gopls mcp -instructions". Use --no-hooks to skip the Claude hook script and
settings wiring (git hooks have their own --no-git-hooks), or --print-hooks to
inspect the resolved hooks block without writing.

Choosing which skills to install requires exactly one of --all, --skills, or
--router-only. With none given on an interactive terminal, install prompts with
a numbered list of every skill (id, one-line description, mandatory skills
shown pre-selected and locked); accepts "1,4,7-9" ranges, "a" for all, or Enter
for the mandatory-only baseline. With none given and no terminal (e.g. CI), it
fails naming the fix rather than guessing. project-router plus every
always_load skill is always installed and cannot be deselected. A selected
skill whose compose_skills names another skill pulls that skill in too
(transitively, cycle-safe); install prints each one added and which skill
required it, e.g. "pulled in by dependency: usecase-layout (required by
rest-adapter)".

--git-hooks installs git hook scripts into <target>/.git/hooks/ that delegate
to the installed binary; valid names are commit-msg, pre-commit, and
pre-push. Default: commit-msg,pre-commit. An unrecognized name fails the
whole install command before anything is written, naming the valid set. Use
--no-git-hooks to skip the git hook scripts; the binary is still copied to
.git/hooks/ so a hook added later works.

uninstall reverses install. Unlike install, it does not default to the
"claude" target: with no --target it probes the project for every layout it
can detect on disk (a .claude dir, a .codex dir, a .opencode dir / opencode.json,
a root AGENTS.md, or a .cursor/rules dir) and reverses all of them; with --global
and no --target it reverses claude and codex. Pass --target to narrow it to one
layout. It removes the hook wiring from both settings.json
and settings.local.json by default, since it cannot recover which
--hooks-scope install used; pass --hooks-scope to narrow to just one file. The
removal is command-level, so an unrelated command sharing the same hook
matcher group survives. It also removes the gopls entry from .mcp.json, the
marked MCP block from .codex/config.toml, the codex hooks from .codex/hooks.json, the
opencode plugin plus its opencode.json wiring, and the git hooks install wrote
into .git/hooks/. The root AGENTS.md is removed only when its content still
carries the marker install wrote it with, so a hand-authored one is never
touched even when the agents or opencode target is detected. Unless
--keep-skills is given, it also removes every rendered skill and workflow doc
install wrote (recognized by the install marker in SKILL.md/WORKFLOW.md, so a
user's own directory under .claude/skills - and anything else placed inside a
rendered skill's own directory - is never touched); --keep-skills keeps those
docs (and AGENTS.md) but still removes the hook wiring. A merged config file
(settings.json, .mcp.json, opencode.json) uninstall cannot parse as JSON is
left untouched with a warning rather than risking corruption. Running
uninstall against a project install never touched, or running it twice, is
not an error; every step is idempotent, so a partial failure can always be
fixed by re-running.

commitlint validates a commit message against the emoji, format, type, scope, and
body rules. Use --msg "..." for a direct string, --file PATH to read from a
COMMIT_EDITMSG file (the git commit-msg hook passes $1), and --project DIR to
enable emoji-variance against recent git history. Exits non-zero on
error-severity findings.

governance runs the analyzer pipeline (static, AST, architecture, delegation,
rule injection) against the project and prints findings to stderr. Exits non-zero
on any error-severity finding. Use --scope commit in pre-commit hooks for a
lightweight run over files with a staged change that omits delegation and
architecture checks.

By default governance analyzes only files git reports as changed (via
`git status`), so it reports nothing on a clean tree - the fast path the Stop
hook and pre-commit hook rely on. --all-files instead analyzes every source file
git lists (git ls-files, tracked plus untracked-but-not-ignored), minus tool and
dependency directories such as .claude/, testdata/, vendor/ and node_modules/, and
falls back to a filesystem walk (skipping the default dependency and tool
directories) only if git ls-files itself fails; governance requires a git work
tree. A full audit of the whole repository thus sees files the changed-set never
would. Combine with --scope full for a complete governance sweep:
`pulsarules_cli governance --project . --scope full --all-files`.

Findings in generated files are suppressed by default. A file counts as
generated when it carries a generator banner ahead of its first real content
(for Go, `// Code generated ... DO NOT EDIT.` above the package clause), or when
it is a .sql file in a directory holding an Atlas atlas.sum. Detection is by
content, not by a path list, so no consumer repository has to maintain an
exclusion list. The suppressed count is always reported in the footer, never
hidden. --include-generated turns that filter off. It does not disable the
per-line exemptions individual analyzers carry for legitimate machine headers
(top-of-file and big-comment still accept a `// Code generated` line above the
package clause, because that line is correct Go, not a defect to report).

evals grades a produced artifact (code or transcript) against the scenario
suite's machine assertions and prints a pass/fail tally per scenario, plus any
assertion that needs a human judge. Use --artifact PATH to point at the file
to grade and --scenario ID to grade only one scenario instead of the whole
suite. Exits non-zero when a graded assertion fails.

hook dispatches a single Claude Code (or opencode) hook event by mode, reading
the tool/session JSON payload from stdin and writing the hookSpecificOutput
JSON to stdout. Modes: session-start, pre-edit, post-edit, pre-search,
user-prompt, stop, subagent-start, session-end. install wires
this invocation into the target's hook script automatically; there is
normally no reason to invoke it by hand.

With no --root, the binary reads the embedded knowledge snapshot. Pass --root DIR
to read <DIR>/knowledge from disk (dev edits without rebuild).

--log-level (debug|info|warn|error) enables hook execution logging, written to the
path the installed host wrapper supplies via $PULSARULES_LOG_PATH (e.g.
<projectDir>/.claude/hook-execution.log for the claude target, .codex/hook-execution.log
for codex); falls back to $PULSARULES_LOG_LEVEL when unset. Logging is off by default
and costs nothing (no file is created); it also stays off when $PULSARULES_LOG_PATH is
unset (an older installed wrapper, or the binary run by hand), rather than guessing a
location.

clean sweeps the files the governance gate walks that lie inside --project (or
the working directory) and reports every AI watermark marker it finds in .go
and .md; outside a git repository it walks the directory without git's file
list. It reports only, unless --write is passed: then it removes the carriers
no context can justify (zero-width characters, bidi controls, soft hyphens)
and folds exotic spaces to a plain space. It never rewrites an em dash, an
ellipsis, a curly quote, or an invisible that may be load-bearing - inside a
string literal or a fenced block those are data, so they are reported for a
human to judge. Files in a testdata/ directory inside the cleaned directory,
and any extension other than .go and .md, are left alone.
