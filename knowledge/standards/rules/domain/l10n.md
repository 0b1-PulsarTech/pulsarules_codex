# Localization catalogue

> No user-facing string literal outside the message catalogue. Every message declares all of its
> locales together, in one declaration, so a locale can never be left partially translated. Locales
> are a closed enum, not a string tag.

Applies to: any user-facing text - a label, a status, an error message, a navigation entry - in any
project, regardless of language or UI framework. See `l10n-svelte` for the SvelteKit
server-resolution instantiation.

{{define "when"}}
- Adding or editing any user-facing string.
- Adding a new message key to the catalogue.
- Adding a new supported locale.
- Rendering a status, label, or error that came from the backend as a raw code.
{{end}}

{{define "must"}}
1. No user-facing literal exists outside the message catalogue. A raw string reaching a template, a
   route, or a use case - a label, a button caption, an error string, a raw backend status code shown
   unmapped - is a bug, not a shortcut.
2. Every catalogue entry declares every locale it supports in one declaration (for example
   `Message(key, ptBr: '...', en: '...')`), never a per-locale file or a map that a later commit could
   patch for only one language. There is no mechanism by which one locale can exist for a key while
   another does not.
3. Locales are a closed, non-string enum. Adding a locale is adding an enum case, which the compiler
   forces every exhaustive locale switch to handle - a locale is never represented as a bare string
   tag at a decision point.
4. A navigational or catalogue label that names an existing entity (a slice, a route, a resource)
   derives its key from that entity's stable identifier (a slug, for example `nav.<slug>`) instead of
   being stored independently on the entry - so an entry can never point at the wrong entity's label.
5. Group message keys by a dotted prefix per owning area (`nav.*`, `dashboard.*`, `errors.*`) so one
   area's block of keys stays contiguous and a single grep finds every string it owns.
{{end}}

{{define "forbidden"}}
- A user-facing string literal in a template, route, or use case instead of a catalogue entry.
- A catalogue entry that declares only some of its supported locales.
- A bare string standing in for the locale enum at a branch/switch that must translate.
- A raw backend status/enum code rendered to the user unmapped through the catalogue.
- A label key stored independently of the entity it names, instead of derived from that entity's
  stable identifier.
{{end}}

{{define "validation"}}
- [ ] No user-facing literal outside the message catalogue.
- [ ] Every message declares all supported locales in one declaration; none is partially translated.
- [ ] Locales are a closed enum; no bare string tag at a translation decision point.
- [ ] An entity-derived label key stays derived, not independently stored.
- [ ] Message keys are grouped by a dotted prefix per owning area.
{{end}}
