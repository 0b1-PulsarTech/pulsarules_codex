---

Go style governs the baseline shape of every Go file: formatting, identifier and package naming,
three-group imports, named structs over map[string]any at boundaries, and small consumer-declared
interfaces. Reach for it whenever you write or edit any .go file, name a package, type, file, or
test, or declare an interface. It is the always-loaded floor beneath every other Go skill; it
does not decide architecture or placement (see code-placement, design-patterns) - only how the
code you already decided to write is named, formatted, and shaped.
